## Essential session model

Case is facilitator-led educational simulation. A room has a facilitator, a projector/display and participants. Participants answer; the facilitator chooses an authored route. A vote never chooses the route. Running rooms retain their immutable published case snapshot when a draft or publication changes elsewhere.

Workspace membership and case-specific access are separate. The server determines every privileged action. [PERMISSIONS](PERMISSIONS.md) records the complete matrix and its declared unfinished actions; [ARCHITECTURE](ARCHITECTURE.md) records the data and transport contracts. No document grants a client direct database access.

## Room state contract

Only revealed material reaches a display or participant. Facilitator notes, route rationale, unrevealed consequences and source text remain private. The bounded numbers-only structural art descriptor is the documented exception; it contains no clinical narrative. The full case pack goes to the facilitator device in memory only. Case content, display names and answers are text, never HTML or Markdown.

All generated identities use UUIDv7 from the shared identity module or the database helper. Human codes use Crockford base32. URL builders are the only source of application URLs; credentials and personal data never belong in a URL. The Worker uses scoped database RPCs; clients never touch Postgres. Live votes belong to the room Durable Object, with bounded idempotent archive batches.

Participant personal data expires under the current 24-hour-after-room-end policy. A new personal field must join the purge contract. Free text is never journalled. Administrative audit and provider recovery history have separate documented boundaries; no unverified provider recovery claim is an erasure guarantee. The [privacy inventory](PRIVACY-DATA-INVENTORY.md) and [privacy policy](PRIVACY-PRIVACY-POLICY.md) describe the candidate contract, not a new deployed-controller attestation.

## Manual room

During an outage the facilitator may explicitly enter manual mode, choose and reveal authored routes locally and retain a bounded manual segment in sessionStorage. This is not a full case-pack persistence mechanism. Phone voting and online recap capture are unavailable for the manual segment. Recovery retries the same bounded segment rather than inventing a new operation after an ambiguous response.

A room-lab upload acknowledgement can arrive before its new snapshot. Network controls wait for the acknowledged epoch/revision or retain the same segment for retry. Production recovery uses the shared recovery and transport contracts. No successful upload, deployment or clinical approval may be inferred from a browser hint.

## Network resilience

Browser online/offline hints are advisory. Real WebSocket/HTTP server contact determines liveness. Offline invalidates cached evidence even when socket close arrived first; a later genuine reply can restore life. A forced snapshot refresh may repeat equal state but cannot restore an older epoch, revision or display revision.

Responses and retries retain their operation identity. Queue/replay, one-participant identity, stale fencing, manual recovery and public/private projection boundaries must remain covered. Emulated lifecycle events and actual transport cuts are recorded separately from physical-device evidence.
