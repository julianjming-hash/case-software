# Case acceptance scenarios

These scenarios validate the room-state contract in `docs/HANDOFF.md`. A prototype or implementation should not claim synchronisation readiness without demonstrating each one with **independently connected clients**. A single-page simulation does not count.

**Traceability.** Claude owns this document and its numbering. Every `AS-NNN` row is either named in the title of a real test, or listed as pending with its reason in `tests/acceptance-coverage.test.mjs`; that test fails on a row with neither, on a pending row that has gained a test, and on a test naming an id that is not a row. Pending rows show up as `todo` in every `npm test` run. The browser proofs drive the stage C lab (`prototypes/room/index.html`) through `tests/playwright-harness.mjs`: independent windows over a simulated Durable Object, which stands in for independently connected clients until the Phase 1 runtime exists. Ids are append-only; a changed scenario keeps its id and its row is rewritten.

Topologies:
- **DD:** dual-display hospital PC, with the facilitator console and projector window on one machine.
- **SP:** separate paired display.

Where the two differ, the scenario says so.

## Authoring-agent acceptance

V1 scope: in-app gateway only, one zero-retention provider, text only. `Create from resources` and external MCP are V2. There is no clinical verification step.

- Agent sees only author-selected safe source fragments and current role-filtered draft context; no images, media or participant data reach a model.
- Agent proposes semantic draft changes with `expected_revision`; no direct database, publish, session, or raw asset access.
- The author sees grouped beat/path changes, dependencies, validation results, and claims/sources, and accepts explicitly.
- A partial acceptance revalidates the draft and cannot create an invalid path graph, including a rejoin that violates entry conditions.
- Proposed text renders as plain text everywhere (diff, builder, projector). Markup in a source or model output is never executed.
- Instructions embedded in a source fragment do not change agent behaviour or permissions.
- Published versions are immutable and every live session pins one version.
